Gemma Studio Field Guide

A private chat AI for friends and family, running on one Mac Studio on your network. It's a Unix box with two services under launchd, driven entirely over SSH. This page shows how the pieces fit, what happens at boot, and what to do when it lands on your LAN.

Arrival

Moving it to your network

Nothing needs reconfiguring

It's set up on a different LAN than yours, but no config file, script or service holds an IP address. Open WebUI listens on 0.0.0.0:8080 and the model server on 127.0.0.1:1234. Plug it into your network and it takes whatever address your DHCP server hands out.

  1. Connect Ethernet and power. Wi-Fi works too, but wired is steadier for a server.
  2. It powers on and starts everything by itself in about a minute. Find its address in your router's DHCP lease table (look for M1-Studio), then ssh houdini@ that address.
  3. Make a DHCP reservation for that address on your router, so family bookmarks keep working.
  4. On the same subnet, M1-Studio.local works too (mDNS/Bonjour). It doesn't cross subnets or VLANs; use the IP or a DNS entry there.
  5. Run the health check: ~/ZuulRulez/gemma/rebuild/40-verify.sh. Exit status is the number of failures.
  6. Open http://its address:8080 in a browser.
Boot sequence

From power cord to first chat

It restarts on its own after a power cut (pmset autorestart 1) and needs nobody: FileVault is off by choice, so there is no unlock step. Measured: everything answers about a minute after power-on.

  1. Power on

    Firmware and the kernel boot. FileVault is off, so there is no unlock screen to wait at.

  2. launchd

    Loads the plists in /Library/LaunchDaemons, like systemd units at multi-user.target.

  3. Model server

    com.gemma.llm loads about 16 GB of weights onto the GPU, offline.

  4. Open WebUI

    com.openwebui.serve answers on :8080. Nobody logs in on the desktop.

Hardening

Siri, Apple Intelligence and 63 background services: off

A single-purpose server doesn't need iCloud, Messages, Siri or analytics. Turning them off in Settings didn't stick, so two mechanisms do it and a boot daemon keeps it that way.

RemoveMacAI profile

A configuration profile that blocks Siri and Apple Intelligence. It also stalls macOS downloads, so it comes off before every OS update and goes back on after.

bash ~/ZuulRulez/gemma/rebuild/50-harden.sh status

Service toggles

launchctl disable overrides for 63 services. macOS 27 resets some early in boot, so com.macos-service-toggle.reassert re-applies them at every boot. Never touched: sshd, Remote Management, Time Machine, watchdogd, rapportd.

sudo /usr/local/bin/macos-service-toggle.sh status

  1. Healthy: system services read [still disabled], nothing reads DRIFTED. Per-user gui/501 entries read [unknown/not found] when nobody is logged in on the desktop; that's normal.
  2. macOS update: 10-upgrade-os.sh (offers to remove the profile) → update → 50-harden.sh profile → 40-verify.sh. If a download stalls anyway: toggles off, update, on again (mobileassetd is on the list).
  3. Undo all of it: sudo /usr/local/bin/macos-service-toggle.sh off, then sudo launchctl bootout system/com.macos-service-toggle.reassert. Logs and state: /usr/local/var/macos-service-toggle/.

Your own notes

Keeping docs and scripts, Git optional

~/ZuulRulez came over as a Git checkout, but you can treat it as a plain folder. Nothing on the box needs Git to run.

  1. Leave ~/ZuulRulez where it is. The model daemon, the ~/bin links and 40-verify.sh point into it.
  2. Keep your own material in a separate folder, for example ~/admin/ for notes, your scripts and runbooks. Machine settings belong in ~/.config/gemma.env, not in the scripts.
  3. Dated snapshots: tar czf ~/admin/snapshot-$(date +%F).tgz -C ~ ZuulRulez .config/gemma.env admin, then copy them wherever you keep backups.
  4. If you want history after all: Git is installed. git -C ~/ZuulRulez status lists anything you've changed in the build folder.
  5. The first chat in Open WebUI (as houdini) is the handoff for this machine. Ask Gemma about the box there.
Handover

First day with it

  • Change houdini's password in System Settings → Users & Groups (Screen Sharing), so login and sudo use your own.
  • The disk is not encrypted (FileVault off, so it restarts unattended). Keep the Mac somewhere private. To encrypt anyway: sudo fdesetup enable -user houdini; then every reboot waits for an SSH login to unlock it.
  • Sign in to Open WebUI as the admin account and change its password. New sign-ups wait as pending until you approve them under Admin Panel → Users; approved users all see the model.
  • Add your SSH key: ssh-copy-id houdini@studio
  • Your call: web search. It's off, so chats have no internet toggle. To turn it on: Admin Panel → Settings → Web Search, enable it, pick an engine (DuckDuckGo needs no key; Brave or Tavily need one; SearXNG can be self-hosted). Each search adds its results to the prompt, roughly 13 s of extra wait per 5,000 tokens on this M1.
  • Your call: tools. Nothing is wired in yet. Open WebUI can give the model access to local folders, GitHub or other code hosts, either as Python tools (Workspace → Tools) or as OpenAPI/MCP tool servers (admin settings, external tools). Limit a folder tool to one dedicated folder, give a GitHub token read-only access to just the repos it needs, and decide whether family members get tools or only you. Tools run on the Studio as houdini.
  • Screen Sharing from Linux: any VNC client on port 5900 works once a VNC password is set in System Settings → General → Sharing → Remote Management → Options.
  • Back up ~/open-webui-data: that's every account and chat. The model files can always be downloaded again.
  • OS updates: run bash ~/ZuulRulez/gemma/rebuild/10-upgrade-os.sh over SSH. It first removes the RemoveMacAI profile (it blocks macOS downloads); afterwards reinstall it with 50-harden.sh profile. 40-verify.sh fails until you do. The update needs houdini's password.
  • Don't run the repo's top-level ./install.sh. It belongs to a different machine's setup.
